# 📅 Bài tập Scheduling — kiểu thi CKA

Luyện điều khiển nơi Pod chạy: taints/tolerations, affinity, và resources/QoS — những dạng ra thi CKA rất thường xuyên.

## Phần 1 — Bài tập thực hành

<PracticeTask level="CKA" time="~6 phút" title="Taint node + Toleration cho Pod">

**Bối cảnh:** Node `node01` chỉ dành cho workload đặc biệt. Bạn cần taint nó và cho một Pod được phép chạy lên đó.

**Nhiệm vụ:**
1. Taint `node01` với `dedicated=special:NoSchedule`.
2. Tạo Pod `special-app` (image `nginx`) có toleration khớp taint đó.

<Solution>

```bash
kubectl taint nodes node01 dedicated=special:NoSchedule
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: special-app
spec:
  tolerations:
    - key: "dedicated"
      operator: "Equal"
      value: "special"
      effect: "NoSchedule"
  containers:
    - name: app
      image: nginx:1.27
```

**Giải thích:** Taint `NoSchedule` "đẩy" mọi Pod không có toleration khớp. Toleration chỉ **cho phép** (không ép) Pod chạy lên node bị taint — muốn ép đúng node đó cần kèm `nodeSelector`/affinity.

**Bẫy hay gặp:** Xoá taint thêm dấu trừ: `kubectl taint nodes node01 dedicated=special:NoSchedule-`. `NoExecute` còn evict Pod đang chạy nếu thiếu toleration.

</Solution>

</PracticeTask>

<PracticeTask level="CKA" time="~6 phút" title="Node Affinity: ép Pod lên node có SSD">

**Bối cảnh:** Chỉ node gắn nhãn `disktype=ssd` mới đủ nhanh cho DB.

**Nhiệm vụ:**
1. Gắn nhãn `disktype=ssd` cho `node01`.
2. Tạo Pod `db` chỉ được xếp lên node có nhãn đó (requiredDuringScheduling).

<Solution>

```bash
kubectl label nodes node01 disktype=ssd
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: db
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
          - matchExpressions:
              - key: disktype
                operator: In
                values: ["ssd"]
  containers:
    - name: db
      image: nginx:1.27
```

**Giải thích:** `requiredDuringScheduling...` là ràng buộc **cứng** — không có node khớp thì Pod `Pending`. `nodeSelector` cũng làm được nhưng affinity hỗ trợ toán tử (`In`, `NotIn`, `Exists`) và luật `preferred` (mềm).

**Bẫy hay gặp:** `IgnoredDuringExecution` = nếu nhãn node đổi sau khi Pod đã chạy thì Pod không bị evict.

</Solution>

</PracticeTask>

<PracticeTask level="CKA" time="~5 phút" title="Requests/Limits và QoS Guaranteed">

**Bối cảnh:** Pod `cache` cần được đảm bảo tài nguyên (QoS **Guaranteed**) để không bị evict trước.

**Nhiệm vụ:** Tạo Pod `cache` sao cho QoS = Guaranteed.

<Solution>

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: cache
spec:
  containers:
    - name: redis
      image: redis:7
      resources:
        requests:
          cpu: "250m"
          memory: "256Mi"
        limits:
          cpu: "250m"
          memory: "256Mi"
```

```bash
kubectl get pod cache -o jsonpath='{.status.qosClass}'   # => Guaranteed
```

**Giải thích:** QoS **Guaranteed** khi **mọi** container có `requests == limits` cho **cả** CPU và memory. Guaranteed bị evict sau cùng khi node thiếu tài nguyên.

**Bẫy hay gặp:** Chỉ đặt limits mà thiếu requests → K8s tự set requests = limits (vẫn Guaranteed). Thiếu một trong hai (cpu/mem) hoặc requests≠limits → tụt xuống **Burstable**.

</Solution>

</PracticeTask>
