# 🔧 Bài tập Cluster Maintenance — kiểu thi CKA

Ba kỹ năng vận hành hay ra thi CKA và dễ mất điểm nhất: **drain node**, **nâng cấp kubeadm**, và **backup/restore etcd**.

## Phần 1 — Bài tập thực hành

<PracticeTask level="CKA" time="~5 phút" title="Drain node để bảo trì rồi đưa lại vào cluster">

**Bối cảnh:** Cần bảo trì `node01`. Phải chuyển hết Pod đi an toàn, kể cả khi có DaemonSet và Pod dùng emptyDir.

**Nhiệm vụ:** Drain `node01` an toàn, sau khi bảo trì xong thì cho nhận Pod trở lại.

<Solution>

```bash
# Đánh dấu unschedulable + evict Pod (bỏ qua DaemonSet, xoá dữ liệu emptyDir)
kubectl drain node01 --ignore-daemonsets --delete-emptydir-data

# ... bảo trì OS/kernel ...

# Cho node nhận Pod trở lại
kubectl uncordon node01
```

**Giải thích:** `drain` = `cordon` (đánh dấu unschedulable) + evict Pod. `--ignore-daemonsets` là **bắt buộc** vì DaemonSet Pod không drain được (controller sẽ tạo lại). `--delete-emptydir-data` cần khi có Pod dùng emptyDir (dữ liệu sẽ mất).

**Bẫy hay gặp:** Thiếu `--ignore-daemonsets` → lệnh drain báo lỗi và dừng. Pod "trần" (không thuộc controller) cần `--force`. Nhớ `uncordon` sau khi xong nếu không node sẽ mãi không nhận Pod.

</Solution>

</PracticeTask>

<PracticeTask level="CKA" time="~9 phút" title="Nâng cấp cluster bằng kubeadm (đúng thứ tự)">

**Bối cảnh:** Nâng control-plane node lên `v1.31.1` trước, rồi tới worker.

**Nhiệm vụ:** Nêu đúng trình tự lệnh nâng cấp control-plane và worker.

<Solution>

```bash
# ===== CONTROL PLANE =====
# 1) Nâng kubeadm
apt-get update && apt-get install -y kubeadm=1.31.1-*
kubeadm version

# 2) Xem kế hoạch & áp dụng
kubeadm upgrade plan
kubeadm upgrade apply v1.31.1

# 3) Drain control-plane, nâng kubelet+kubectl, restart
kubectl drain <cp-node> --ignore-daemonsets
apt-get install -y kubelet=1.31.1-* kubectl=1.31.1-*
systemctl daemon-reload && systemctl restart kubelet
kubectl uncordon <cp-node>

# ===== WORKER (làm lần lượt từng node) =====
kubectl drain <worker> --ignore-daemonsets --delete-emptydir-data
# trên worker:
apt-get install -y kubeadm=1.31.1-*
kubeadm upgrade node
apt-get install -y kubelet=1.31.1-* kubectl=1.31.1-*
systemctl daemon-reload && systemctl restart kubelet
# trở lại control plane:
kubectl uncordon <worker>
```

**Giải thích:** Thứ tự bắt buộc: **control plane trước, worker sau**. Control plane dùng `kubeadm upgrade apply`; worker dùng `kubeadm upgrade node`. Luôn drain trước khi nâng kubelet, uncordon sau.

**Bẫy hay gặp:** Tuân version skew — kubelet không được mới hơn kube-apiserver. Nâng từng minor một (không nhảy 1.29→1.31).

</Solution>

</PracticeTask>

<PracticeTask level="CKA" time="~8 phút" title="Backup và restore etcd snapshot">

**Bối cảnh:** Trước khi thao tác rủi ro, cần snapshot etcd; sau sự cố cần restore.

**Nhiệm vụ:** Tạo snapshot etcd và restore vào data-dir mới.

<Solution>

```bash
# BACKUP — luôn dùng API v3 + cert của etcd
ETCDCTL_API=3 etcdctl snapshot save /opt/etcd-backup.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

ETCDCTL_API=3 etcdctl snapshot status /opt/etcd-backup.db --write-out=table

# RESTORE — vào thư mục MỚI
ETCDCTL_API=3 etcdctl snapshot restore /opt/etcd-backup.db \
  --data-dir=/var/lib/etcd-restored

# Rồi sửa static pod manifest để trỏ tới data-dir mới:
#   /etc/kubernetes/manifests/etcd.yaml
#   volume hostPath.path + --data-dir => /var/lib/etcd-restored
# kubelet sẽ tự restart etcd với dữ liệu đã restore.
```

**Giải thích:** etcd là "bộ não" — snapshot là cách backup toàn bộ state cluster. Restore tạo data-dir mới; phải cập nhật manifest `etcd.yaml` (data-dir + hostPath volume) để etcd dùng data-dir đó.

**Bẫy hay gặp:** Quên `ETCDCTL_API=3` (mặc định cũ khác lệnh). Đường dẫn cert sai là lỗi phổ biến nhất — lấy đúng từ `etcd.yaml`. Không restore đè lên data-dir đang chạy.

</Solution>

</PracticeTask>
