# 🔐 Bài tập Security — kiểu thi CKS

Các bài tập dưới đây mô phỏng **định dạng hands-on của kỳ thi CKS**: mỗi bài là một tình huống có ngữ cảnh + yêu cầu, bạn tự viết YAML/lệnh `kubectl` rồi bấm **Xem lời giải** để đối chiếu.

:::tip Cách luyện đúng kiểu thi
Tự bấm giờ, gõ lời giải bằng `kubectl`/YAML thật trong đầu (hoặc trên cluster luyện tập) **trước khi** mở đáp án. Kỳ thi CKS chấm bằng kết quả trên cluster, không phải trắc nghiệm.
:::

## Phần 1 — Bài tập thực hành

<PracticeTask level="CKS" time="~8 phút" title="NetworkPolicy: default-deny ingress + chỉ cho phép frontend">

**Bối cảnh:** Namespace `prod` chứa Pod `backend` (label `app=backend`) lắng nghe cổng `8080`. Namespace `frontend` (label `kubernetes.io/metadata.name=frontend`) cần gọi được `backend:8080`. Mọi nguồn khác phải bị chặn.

**Nhiệm vụ:**
1. Tạo policy **default-deny toàn bộ ingress** cho namespace `prod`.
2. Tạo policy cho phép ingress tới Pod `app=backend` cổng `8080` **chỉ** từ namespace `frontend`.

<Solution>

```yaml
# 1) default-deny mọi ingress trong namespace prod
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: prod
spec:
  podSelector: {}          # áp cho MỌI pod trong prod
  policyTypes:
    - Ingress              # không có rule ingress => chặn hết
---
# 2) chỉ cho phép từ namespace frontend tới backend:8080
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-backend
  namespace: prod
spec:
  podSelector:
    matchLabels:
      app: backend
  policyTypes:
    - Ingress
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: frontend
      ports:
        - protocol: TCP
          port: 8080
```

**Giải thích:** `podSelector: {}` + `policyTypes: [Ingress]` mà không có `ingress:` = chặn toàn bộ ingress. NetworkPolicy có tính **cộng dồn (additive)** nên policy thứ hai mở đúng một lối vào cho `frontend`.

**Bẫy hay gặp:** NetworkPolicy chỉ có tác dụng nếu CNI hỗ trợ (Calico, Cilium…). `namespaceSelector` khớp theo **label của namespace**, không phải tên — nhớ label `kubernetes.io/metadata.name` được K8s tự gắn từ v1.21.

</Solution>

</PracticeTask>

<PracticeTask level="CKS" time="~6 phút" title="Hardening securityContext cho Pod">

**Bối cảnh:** Pod `web` đang chạy bằng `root`, cho phép privilege escalation và ghi được vào rootfs — vi phạm baseline bảo mật.

**Nhiệm vụ:** Cấu hình lại để container chạy **non-root (uid 1000)**, **không** escalate privilege, **drop toàn bộ** Linux capabilities, và **rootfs chỉ đọc**.

<Solution>

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    seccompProfile:
      type: RuntimeDefault
  containers:
    - name: web
      image: nginx:1.27
      securityContext:
        allowPrivilegeEscalation: false
        readOnlyRootFilesystem: true
        capabilities:
          drop: ["ALL"]
      volumeMounts:                 # nginx cần ghi tạm => cấp emptyDir
        - name: tmp
          mountPath: /tmp
  volumes:
    - name: tmp
      emptyDir: {}
```

**Giải thích:** `runAsNonRoot` + `runAsUser` ép uid non-root; `allowPrivilegeEscalation: false` chặn setuid leo thang; `drop: ["ALL"]` bỏ mọi capability; `readOnlyRootFilesystem: true` khoá rootfs. `seccompProfile: RuntimeDefault` là yêu cầu của Pod Security *restricted*.

**Bẫy hay gặp:** app cần ghi (nginx pid/tmp) sẽ crash khi rootfs read-only → mount `emptyDir` vào đúng thư mục. `capabilities` đặt ở **container-level**, không phải pod-level.

</Solution>

</PracticeTask>

<PracticeTask level="CKS" time="~6 phút" title="RBAC least-privilege cho ServiceAccount CI">

**Bối cảnh:** Pipeline CI dùng ServiceAccount `ci` trong namespace `dev`. Nó chỉ được **xem** (get/list/watch) Pod trong `dev` — không hơn.

**Nhiệm vụ:** Tạo `ServiceAccount`, `Role`, `RoleBinding` đúng nguyên tắc least-privilege và kiểm chứng bằng `kubectl auth can-i`.

<Solution>

```bash
kubectl -n dev create serviceaccount ci

kubectl -n dev create role pod-reader \
  --verb=get,list,watch --resource=pods

kubectl -n dev create rolebinding ci-pod-reader \
  --role=pod-reader --serviceaccount=dev:ci

# Kiểm chứng:
kubectl -n dev auth can-i list pods \
  --as=system:serviceaccount:dev:ci        # => yes
kubectl -n dev auth can-i delete pods \
  --as=system:serviceaccount:dev:ci        # => no
```

**Giải thích:** Dùng `Role` + `RoleBinding` (namespaced) thay vì `ClusterRole` để giới hạn phạm vi đúng namespace `dev`. `auth can-i --as=system:serviceaccount:<ns>:<sa>` là cách kiểm tra quyền của SA nhanh nhất trong phòng thi.

**Bẫy hay gặp:** Đừng dùng `ClusterRoleBinding` (cấp toàn cluster). Format subject của SA luôn là `system:serviceaccount:<namespace>:<name>`.

</Solution>

</PracticeTask>
